### Em 2024-1 | API 1º semestre — Calculadora Científica

### Empresa Parceira: FATEC São José dos Campos (projeto interno)

**Papel na equipe:** Desenvolvedor

### Problema:
Os alunos da disciplina de Organização de Computadores precisavam fazer operações matemáticas e conversões entre bases numéricas (binário, octal, decimal e hexadecimal) sem uma ferramenta prática e unificada. Os cálculos eram feitos à mão, o que aumentava a chance de erro e deixava o aprendizado menos eficiente. O professor da disciplina assumiu o papel de cliente e apresentou os requisitos à equipe.

### Solução Entregue pela Equipe:
A equipe desenvolveu uma calculadora científica com interface de texto que permite realizar várias operações na mesma execução. Os algoritmos foram construídos primeiro em Portugol, no Visualg, e depois migrados para TypeScript, executado no terminal. Além das quatro operações básicas, a calculadora resolve fatorial, equação do segundo grau (Bhaskara), juros simples e compostos, concatenação de strings e conversões entre bases. Para reforçar a proposta pedagógica, cálculos como a raiz quadrada foram implementados manualmente, sem usar as funções prontas da linguagem.

[Repositório do Projeto](https://github.com/DenariusData/API-1sem)

#### Principais Funcionalidades

- Menu interativo no terminal, com várias operações por execução.
- Operações básicas: adição, subtração, multiplicação e divisão.
- Cálculo de fatorial e resolução de equação do segundo grau (Bhaskara).
- Juros simples e juros compostos.
- Concatenação de strings.
- Conversão entre as bases decimal, binária, octal e hexadecimal.
- Validação das entradas do usuário.

export function hexadecimalParaBinario(hexadecimal: string): string {
    const caracteresHexadecimais = '0123456789ABCDEF';
    let decimal = 0;
    for (let i = 0; i < hexadecimal.length; i++) {
        let char = garantiaMai(hexadecimal[i]);
        let valor = 0;
        for (let j = 0; j < caracteresHexadecimais.length; j++) {
            if (caracteresHexadecimais[j] === char) {
                valor = j;
                break;
            }
        }
        decimal = decimal * 16 + valor;
    }
    return decimalParaBinario(decimal);
}

### Em 2024-2 | API 2º semestre — PACER

### Empresa Parceira: FATEC São José dos Campos (projeto interno)

**Papel na equipe:** Desenvolvedor

### Problema:
Na metodologia de Aprendizagem por Projetos Integrados, os alunos avaliam os colegas de equipe ao final de cada sprint (PACER). Esse processo era feito em papel ou planilhas, o que deixava os dados difíceis de organizar, comparar e analisar. ### Solução Entregue pela Equipe:
A equipe desenvolveu uma aplicação desktop em Java com JavaFX para a avaliação entre os membros das equipes ao final de cada sprint. Os dados ficam armazenados em MySQL e o sistema gera relatórios com as médias por aluno e por grupo. A aplicação permite gerenciar os grupos, personalizar os critérios de avaliação, controlar automaticamente o calendário das sprints e autenticar os usuários, com recuperação de senha pelo RA.

[Repositório do Projeto](https://github.com/DenariusData/API-2SEM)

#### Principais Funcionalidades

- Login de alunos e professores, com recuperação de senha pelo RA.
- Avaliação entre os membros da equipe ao final de cada sprint.
- Atribuição de pontos por sprint para cada equipe.
- Personalização dos critérios de avaliação pelo professor.
- Gerenciamento de grupos e alunos.
- Controle automático do calendário das sprints.
- Relatórios em Excel com médias por aluno e por grupo, filtrados por sprint.

private Double calcularExcessoVelocidadeComRegistros(List<RegistroVelocidade> registros) {
    List<RegistroVelocidade> regs = registros.stream()
            .filter(r -> r.getVelocidadeRegistrada() != null && r.getRadar() != null
                    && r.getRadar().getVelocidadePermitida() != null)
            .collect(Collectors.toList());

    if (regs.isEmpty()) {
        return 1.0;
    }

    long excessos = regs.stream()
            .filter(r -> r.getVelocidadeRegistrada() > r.getRadar().getVelocidadePermitida())
            .count();

    double percentualExcessos = (double) excessos / regs.size() * 100;

    if (percentualExcessos <= 10) {
        return 1.0;
    } else if (percentualExcessos <= 25) {
        return 2.0;
    } else {
        return 3.0;
    }
}

**Papel na equipe:** Desenvolvedor Backend e de Observabilidade

### Problema:
A análise de jurisprudência é feita de forma manual e fragmentada. Advogados e juízes não conseguem identificar com segurança como os tribunais vêm decidindo sobre uma tese, ou seja, qual é o índice de aceitação, quantas vezes ela aparece e o quanto o entendimento está consolidado. Hoje isso exige pesquisar decisão por decisão nos sites dos tribunais e tabular os resultados em planilhas, sem garantia de rastreabilidade das fontes.

### Solução Entregue pela Equipe:
A equipe está desenvolvendo o Ratio (do latim *ratio decidendi*, o fundamento determinante de uma decisão judicial), uma plataforma que centraliza e analisa jurisprudência, precedentes e doutrina do TJSP, TJRJ, TJMG, STJ e STF em um Data Warehouse jurídico. O usuário descreve o caso em linguagem natural e recebe os temas jurídicos já identificados, ordenados pela força do entendimento. Para cada tema, o sistema mostra o padrão de decisão (taxa de procedência, volume e tribunais), um score de 0 a 100 com classificação na linguagem do meio jurídico (Consolidada, Dominante, Em formação, Divergente), a evolução ano a ano e por tribunal, uma amostra auditável dos processos e a doutrina e os precedentes qualificados relacionados. Todo número exibido leva à sua fonte e à data de extração.

[Repositório do Projeto](https://github.com/Concord-API/API-5) · [Backend](https://github.com/Concord-API/API5-Backend) · [Frontend](https://github.com/Concord-API/API5-Frontend) · [Pipeline](https://github.com/Concord-API/API5-Pipeline)

#### Principais Funcionalidades

- Busca de temas jurídicos em linguagem natural.
- Resultados ordenados pela força do entendimento, e não pela relevância do texto.
- Score de 0 a 100 com classificação: Consolidada, Dominante, Em formação ou Divergente.
- Leitura do entendimento em texto, com a distribuição dos resultados (procedente, parcialmente procedente e improcedente).
- Evolução do alinhamento ano a ano e comparação do comportamento de cada tribunal.
- Filtros por tribunal, período, instância e força mínima.
- Amostra auditável dos processos, com acórdãos, precedentes qualificados e doutrina relacionados.
- Rastreabilidade de fonte e data de extração em todos os números, com exportação em CSV e citação pronta para copiar.
